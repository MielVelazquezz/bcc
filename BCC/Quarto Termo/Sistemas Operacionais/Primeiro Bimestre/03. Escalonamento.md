## Objetivos do escalonamento

> [!question] Por que isso importa? 
> Porque a CPU é um recurso único e vários processos "brigam" por ela. O objetivo muda dependendo do tipo de sistema.

| Tipo de sistema                                                             | Objetivos                                                                                                                      |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Todos os sistemas**                                                       | Justiça (CPU distribuída de forma justa), aplicar a política definida, manter todas as partes do sistema ocupadas (equilíbrio) |
| **[[00. Palavras-Chave#Sistema em Lote (Batch)\|Sistema em Lote (Batch)]]** | Vazão ([[00. Palavras-Chave#Throughput (vazão)\|throughput]]) alta, minimizar tempo de retorno, manter a CPU sempre ocupada    |
| **[[00. Palavras-Chave#Sistemas Interativos\|Sistemas Interativos]]**       | Responder rápido, atender a expectativa do usuário (proporcionalidade)                                                         |
| **Tempo Real**                                                              | Cumprir prazos ([[00. Palavras-Chave#Deadlines (prazos)\|deadlines]]), ser previsível                                          |

---
## Dois tipos fundamentais de escalonamento
#### Não-preemptivo (Sistemas em Lote)
- Uma vez que o processo pega a CPU, **só sai quando termina ou bloqueia sozinho** (ex: espera de I/O).
- Não existe "interrupção forçada" pelo SO.
- Usado nos primeiros sistemas multiprogramáveis (processamento _batch_).

#### Preemptivo (Sistemas Interativos)
- O SO **pode interromper** um processo em execução para dar a vez a outro.
- Usado em sistemas de tempo compartilhado.
- Permite tratar processos de maior prioridade.

> [!tip] Como lembrar **Pre**emptivo = o SO **pré**-decide tirar a CPU de alguém no meio. Não-preemptivo = deixa o processo "terminar o que começou".

---

## Definições

> [!warning]
>
> **Tempo de Espera** → tempo que o processo fica **parado na fila de prontos**, sem executar.
> 
> **Tempo de Retorno ([[00. Palavras-Chave#Turnaround (tempo de retorno)|Turnaround]])** → tempo **total** desde a chegada até o término. $$\text{Tempo de Retorno} = \text{Tempo de Término} - \text{Tempo de Chegada}$$

## Algoritmos Não-Preemptivos
### [[00. Palavras-Chave#FCFS (First-Come, First-Served)|FIFO / FCFS]] (First-In-First-Out / First Come First Served)
- Quem chega primeiro, executa primeiro.
- Usa **uma única fila**; processos entram no final e são atendidos pelo início.
- **Problema**: impossível prever quando um processo vai começar a rodar, pois depende de quem está na frente.

#### Exemplo resolvido (FIFO)
![[Pasted image 20260916095039.png]]

| Processo | Tempo de CPU |
| -------- | ------------ |
| P1       | 24           |
| P2       | 3            |
| P3       | 3            |

**Ordem de chegada P1, P2, P3:**
- Tempo de espera: P1=0, P2=24, P3=27
- **Tempo médio de espera = (0+24+27)/3 = 17**

**Ordem de chegada P2, P3, P1** (mesmos processos, ordem diferente!):

```
| P2 (0-3) | P3 (3-6) | P1 (6-30) |
```

- Tempo de espera: P2=0, P3=3, P1=6
- **Tempo médio de espera = (6+0+3)/3 = 3**

> [!important] Conclusão do exemplo A **ordem de chegada muda completamente** o desempenho do FIFO (17 vs 3 de espera média). Isso mostra a fraqueza do algoritmo.

---
## [[00. Palavras-Chave#SJF (Shortest Job First)|SJF]] (Shortest Job First) -> Job mais curto primeiro
- Escolhe sempre o processo com **menor tempo de execução**.
- Favorece processos curtos.
- **Problema**: é difícil saber, com exatidão, quanto tempo de CPU cada processo vai precisar.

#### Exemplo resolvido (SJF não-preemptivo)

| Processo | Chegada | Tempo de CPU |
| -------- | ------- | ------------ |
| P1       | 0       | 7            |
| P2       | 2       | 4            |
| P3       | 4       | 1            |
| P4       | 5       | 4            |

Escolhe P1 (só ele chegou em 0). Quando P1 termina (t=7), todos já chegaram → escolhe o de menor tempo restante entre os que já chegaram.

```
| P1 (0-7) | P3 (7-8) | P2 (8-12) | P4 (12-16) |
```

- Tempo de espera: P1=0, P2=6, P3=3, P4=7
- **Tempo médio de espera = (0+6+3+7)/4 = 4**

> [!note] Regra de ouro do SJF não-preemptivo Uma vez a CPU alocada a um processo, **não é tirada dele** antes de terminar — mesmo que chegue algo mais curto depois.

## Algoritmos Preemptivos

### [[00. Palavras-Chave#Round Robin|Round Robin]] (Escalonamento Circular)
- Usa o conceito de **quantum** (fatia de tempo fixa).
- O processo no início da fila roda por um quantum; se não terminar, vai pro **final da fila**.
- Fila de prontos tratada como **fila circular**.

> [!warning] Escolha do quantum é crítica
> 
> - **Quantum muito curto** → muita troca de contexto → [[00. Palavras-Chave#Overhead (sobrecarga)|overhead]] alto, CPU perde eficiência.
> - **Quantum muito longo** → resposta ruim pra processos interativos curtos → tende a virar FIFO.
> - **Quantum ideal**: em torno de **10 a 100 ms**.

#### Exemplo resolvido (Round Robin, sem considerar chegada)

| Processo | Tempo de CPU | Quantum |
| -------- | ------------ | ------- |
| P1       | 14           | 4       |
| P2       | 3            |         |
| P3       | 3            |         |

```
| P1 (0-4) | P2 (4-7) | P3 (7-10) | P1 (10-14→ termina em 20) |
```

> [!caution] Cuidado Quando um processo roda mais de uma vez, **desconsiderar os tempos em que ele ficou parado** no meio para calcular espera/retorno.

- Tempo médio de espera = ((10-4) + 4 + 7) / 3 ≈ **5,6 ms**
- Tempo médio de retorno = (14+7+10)/3 ≈ **10,3 ms**

#### Exemplo resolvido (Round Robin, considerando chegada)

| Processo | Tempo CPU | Chegada | Quantum |
| -------- | --------- | ------- | ------- |
| P1       | 8         | 0       | 4       |
| P2       | 4         | 1       |         |
| P3       | 9         | 2       |         |
| P4       | 5         | 3       |         |

```
| P1(0-4) | P2(4-8) | P3(8-12) | P4(12-16) | P1(16-20) | P3(20-24) | P4(24-25) | P3(25-26) |
```

- Tempo médio de espera ≈ **11,75 ms**
- Tempo médio de retorno ≈ **18,25 ms**

---
#### SRTF (Shortest Remaining Time First) — versão preemptiva do SJF
- Se chegar um **novo processo com tempo de CPU menor que o tempo restante** do processo em execução → ocorre a **[[00. Palavras-Chave#Preempção|preempção]]** (troca).
- Regra: **considerar o menor tempo de CPU restante** para decidir se troca.

#### Exemplo resolvido (SRTF)

| Processo | Chegada | Tempo de CPU |
| -------- | ------- | ------------ |
| P1       | 0.0     | 7            |
| P2       | 2.0     | 4            |
| P3       | 4.0     | 1            |
| P4       | 5.0     | 4            |

```
| P1(0-2) | P2(2-4) | P3(4-5) | P2(5-7) | P4(7-11) | P1(11-16) |
```

- **Tempo médio de espera = (9+1+0+2)/4 = 3**

> [!tip] Como calcular cada tempo de espera no SRTF Espera = (momento em que **termina** de executar pela última vez) − (tempo total de CPU do processo) − (tempo de chegada) Ex: P1 → 16 − 7 − 0 = 9 ✅ (bate com o cálculo do slide, considerando os intervalos em que ficou parado)

## [[00. Palavras-Chave#Escalonamento por Prioridade|Escalonamento por Prioridades]]
- Cada processo recebe uma **prioridade**.
- Processo de **maior prioridade** roda primeiro; um de menor prioridade cede a CPU se chegar algo mais prioritário.

> [!danger] Problema clássico: [[00. Palavras-Chave#Starvation (inanição)|Starvation]] Processos de **baixa prioridade** podem nunca rodar, se sempre chegar algo mais prioritário.
> 
> **Solução: [[00. Palavras-Chave#Aging (envelhecimento)|Aging]]** → a prioridade do processo **aumenta com o tempo de espera**, garantindo que ele eventualmente rode.

**Tipos de prioridade:**
- **Estática**: não muda durante a vida do processo.
- **Dinâmica**: ajustada conforme tipo de processamento/carga do sistema.
    - Pelo usuário: comando `nice` do UNIX (diminui prioridade).
    - Pelo sistema: com base em operações de E/S, etc.

---
#### SPN com Aging (Próximo Processo mais Curto)

- Baseado no SJF, mas **estima** o próximo tempo de CPU com base no comportamento passado (já que não dá pra saber com certeza).
- Fórmula de **soma ponderada (aging)**:

$$\tau_{n+1} = \alpha \cdot T_n + (1-\alpha) \cdot \tau_n$$

> [!note] Interpretando o α (alfa)
> 
> - **α = 0** → histórico recente **não importa**, mantém a estimativa antiga ($\tau_{n+1} = \tau_n$)
> - **α = 1** → só o **último** tempo de CPU importa ($\tau_{n+1} = t_n$)
> - Exemplo com α = ½: T0, T0/2+T1/2, T0/4+T1/4...

---
#### Escalonamento Garantido
- Se há **n usuários** conectados, cada um deveria receber **1/n da CPU**.
- O sistema monitora quanto CPU cada processo já recebeu e ajusta (dá mais CPU a quem recebeu menos) pra manter a proporção justa.

#### Escalonamento por Loteria
- Cada processo ganha **bilhetes de loteria**.
- A CPU "sorteia" um bilhete vencedor → dono ganha a CPU.
- Processos parceiros podem **trocar bilhetes** entre si.
- Quanto mais bilhetes, mais chance de ganhar.

#### Fair-Share (Fração Justa)
- Objetivo: **evitar que um usuário com vários processos** monopolize mais CPU do que um usuário com um único processo.
- A fração de CPU é alocada **por usuário**, não por processo.

> [!example] Exemplo do slide Usuário 1 tem processos A, B, C, D. Usuário 2 tem só o processo E. Fila circular fica assim (E aparece o dobro de vezes, proporcionalmente): `A E B E C E D E A E B E C E D E`

## Escalonamento em Tempo Real

> [!info] Quando um sistema de tempo real é "escalonável"? Dado **m eventos periódicos**, onde o evento _i_ ocorre com período $P_i$ e precisa de $C_i$ segundos de CPU, o sistema consegue atender a todos **se e somente se**:
> 
> $$\sum_{i=1}^{m} \frac{C_i}{P_i} \leq 1$$

#### Exemplo resolvido

| Processo | Períodos      | Tempo de CPU |
| -------- | ------------- | ------------ |
| P1       | 100, 200, 500 | 50, 30, 100  |

$$\frac{50}{100}+\frac{30}{200}+\frac{100}{500} = 0,5+0,15+0,2 = 0,85 \leq 1 ;;✅ \text{ escalonável}$$

**E se eu quiser adicionar um 4º evento de 1000 ms, quanto de CPU (x) ele pode usar no máximo?** $$0,85 + \frac{x}{1000} \leq 1 \implies x \leq 150 \text{ ms}$$

#### Tipos de algoritmos de tempo real
- **Estáticos**: decidem tudo **antes** do sistema rodar. Só funcionam com informação perfeita sobre trabalho e prazos.
- **Dinâmicos**: decidem **durante a execução**, sem essas restrições.

## Escalonamento Multinível

> [!info] Ideia Dividir os processos em **grupos** (filas) conforme sua importância/tipo, cada fila com seu próprio algoritmo.

Exemplo clássico:

- Fila **foreground** (processos interativos) → algoritmo **Round Robin**
- Fila **background** (processos batch) → algoritmo **FCFS**

**Como escalonar entre as filas?**

- **Prioridades fixas**: atende toda a fila foreground primeiro, só depois a background.
- **Time slice**: cada fila recebe uma % fixa de CPU (ex: 80% foreground / 20% background).

### Multinível com Feedback

- Processos **podem migrar entre filas** → implementa aging na prática.
- Parâmetros que o escalonador precisa definir:
    1. Número de filas
    2. Algoritmo de cada fila
    3. Quando subir/descer a prioridade de um processo
    4. Em qual fila um processo novo entra

#### Exemplo (3 filas)

- **Q0**: quantum = 8ms (RR) → se não terminar, desce pra Q1
- **Q1**: quantum = 16ms (RR) → se não terminar, desce pra Q2
- **Q2**: FCFS (sem quantum, só espera a vez)

> [!tip] Intuição Processo "leve" (rápido) termina logo em Q0. Processo "pesado" vai afundando nas filas, mas pelo menos garante que vai rodar (evita starvation total).

| Algoritmo   | Preemptivo? | Ideia central                     | Problema principal               |
| ----------- | ----------- | --------------------------------- | -------------------------------- |
| FIFO/FCFS   | Não         | Ordem de chegada                  | Depende muito da ordem           |
| SJF         | Não         | Menor job primeiro                | Difícil prever duração           |
| Round Robin | Sim         | Fatias de tempo (quantum)         | Escolher quantum certo           |
| SRTF        | Sim         | SJF + preempção                   | Overhead de trocas               |
| Prioridades | Sim         | Maior prioridade primeiro         | Starvation (resolvido com aging) |
| SPN + Aging | Sim         | Estima próximo burst              | Depende do α escolhido           |
| Garantido   | Sim         | 1/n de CPU por usuário            | —                                |
| Loteria     | Sim         | Bilhetes/sorteio                  | —                                |
| Fair-share  | Sim         | Justiça por usuário, não processo | —                                |
| Multinível  | Sim         | Filas por tipo de processo        | Configuração complexa            |
