## <mark style="background: #FFB8EBA6;">Sistema de Informação Baseado em Computador (SIBC)</mark>
Sistema que usa tecnologia de computação para coletar, processar, armazenar e distribuir informações, apoiando as operações e a tomada de decisões de uma organização. O SIBC é parte do "sistema empresa".

**Finalidade:** executar certo **método, procedimento ou controle** ao processar informações.

#### <mark style="background: #FFF3A3A6;">Elementos de um SIBC</mark>

| Elemento             | Definição                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Software**         | Programas de computador, estruturas de dados e documentação correlata que efetivam o método/processo/controle lógico necessário |
| **Hardware**         | Dispositivos eletrônicos (capacidade computacional) e eletromecânicos (funções ao mundo externo)                                |
| **Pessoas**          | Usuários e operadores de hardware e software                                                                                    |
| **Banco de dados**   | Grande e organizada coleção de informações acessada pelo software                                                               |
| **Telecomunicações** | Permitem ligar sistemas de computador em redes                                                                                  |
| **Procedimento**     | Passos que definem o uso específico de cada elemento ou o contexto processual do sistema                                        |

Todos giram em torno do **Sistema**, entre **Entrada** e **Saída**.

> [!warning] Cuidado na prova
> IDEs e linguagens de programação **não são** elementos do SIBC. Eles são **ferramentas** usadas para construir o **software** (que é um dos elementos). Os 6 elementos são: software, hardware, pessoas, banco de dados, telecomunicações e procedimento.

## <mark style="background: #FFB8EBA6;">Engenharia de Sistemas de Computador</mark>
- Papel do **engenheiro/analista de sistemas**: definir os elementos de um sistema específico baseado em computador, no contexto da hierarquia global dos sistemas.
- É atividade <mark style="background: #CACFD9A6;">interdisciplinar</mark> destinada a <mark style="background: #CACFD9A6;">solucionar problemas</mark>:
    -  <mark style="background: #CACFD9A6;">Delimitar</mark> função, desempenho, restrições e interfaces
    -  <mark style="background: #CACFD9A6;">Alocar</mark> cada função a um ou mais elementos do sistema (software, hardware, pessoas...)
    -  Alocações alternativas são propostas e avaliadas

Cada elemento tem sua própria "engenharia": Engenharia de **Hardware**, de **Software**, de **Banco de Dados** e **Engenharia Humana** (pessoas).

---
## <mark style="background: #FFB8EBA6;">O que é Software?</mark>
Software **não é só um conjunto de programas**. Ele engloba:
-  **Programas** → quando executados, produzem a função/desempenho desejados
-  **Documentos** → descrevem a operação e o uso dos programas
-  **Estruturas de dados** → permitem que os programas manipulem a informação adequadamente

#### <mark style="background: #FFF3A3A6;">Características do Software</mark>
-  É desenvolvido/<mark style="background: #CACFD9A6;">projetado por engenharia</mark>, não manufaturado no sentido clássico
-  <mark style="background: #CACFD9A6;">Não se desgasta, mas se deteriora</mark>
-  Apesar de a indústria caminhar para a montagem baseada em componentes, a maioria do software ainda é <mark style="background: #CACFD9A6;">construído sob encomenda</mark>

#### <mark style="background: #FFF3A3A6;">Curvas de falha (Hardware x Software)</mark>
- **Hardware**: curva em "banheira" → "mortalidade infantil" (falhas no começo) → estabilidade → **desgaste** (peças envelhecem)
- **Software**: não sofre desgaste físico. Começa estável, mas **cada mudança** (manutenção/atualização) pode introduzir novos defeitos e novos picos de falha → a **curva real** se afasta da **curva idealizada** ao longo do tempo. É isso que chamamos de **deterioração**.

#### <mark style="background: #FFF3A3A6;">Erro, Defeito e Falha</mark>
- **Erro**: engano cometido pelo **ser humano** (o programador entendeu errado a regra)
- **Defeito ("bug")**: o que o erro produz no **código ou documento** (a linha de código errada)
- **Falha**: quando o defeito é **executado**, o sistema falha (o usuário vê o resultado errado)

***Sequência: erro (pessoa) → defeito (código) → falha (execução).***

## <mark style="background: #FFB8EBA6;">Aplicações do Software</mark>

| Tipo | O que faz | Exemplos |
| --- | --- | --- |
| **Básico** | Apoia outros programas | Compiladores, componentes do sistema operacional |
| **Tempo real** | Monitora, analisa e controla eventos do mundo real | Controle de tráfego, sensores |
| **Comercial** | Operações comerciais e decisões administrativas | Folha de pagamento, estoque |
| **Científico e de engenharia** | Algoritmos de processamento numérico/cálculos complexos | Biologia molecular, satélites, manufatura automatizada |
| **Embutido** | Reside na memória **ROM** e controla produtos e sistemas industriais e de consumo | Teclado do micro-ondas |
| **Computador pessoal** | Uso pessoal | Editores de texto, planilhas, entretenimento |
| **Inteligência artificial** | Algoritmos **não numéricos** para problemas que não se resolvem por análise direta | Sistemas especialistas, reconhecimento de padrões (imagem e voz), redes neurais, jogos |
| **Web** | Incorpora instruções executáveis + dados | CGI, HTML, Perl, Java; hipertexto, áudio e visual |

##  <mark style="background: #FFB8EBA6;">Evolução do Software</mark>
- **1950–1965**: hardware mudava muito; software era "arte secundária", sem métodos sistemáticos nem documentação
- **1965–1975**: sistemas multiusuário e de tempo real; 1ª geração de SGBDs; surgem produtos de software (_software houses_)
    - Cresce o nº de sistemas baseados em computador → manutenção quase impossível → **Crise de Software**
- **1975–hoje**: sistemas distribuídos, redes locais/globais, microprocessadores e hardware baratos, produtos inteligentes, orientação a objetos, sistemas especialistas/IA na prática, redes neurais

##  <mark style="background: #FFB8EBA6;">Crise de Software</mark>
Conjunto de problemas encontrados no desenvolvimento de software ("aflição crônica").

#### <mark style="background: #FFF3A3A6;">Problemas</mark>
1. **Prazo e custo imprecisos** (falta de dados históricos de produtividade)
2. **Insatisfação do cliente** com o sistema concluído (requisitos levantados de forma vaga)
3. **Qualidade** do software às vezes inadequada (conceitos de garantia de qualidade ainda recentes)
4. Software existente **muito difícil de manter** (manutenção devora o orçamento; facilidade de manutenção não era priorizada)

#### <mark style="background: #FFF3A3A6;">Causas</mark>
1. **Próprio caráter do software**: é um elemento lógico, não físico → não se desgasta, mas se deteriora
2. **Falhas das pessoas responsáveis pelo desenvolvimento**:
    - Gerentes sem experiência em software
    - Pouco treinamento formal em novas técnicas
    - Resistência a mudanças

***Resumo: software que se deteriora + profissionais pouco qualificados = dificuldade de criar e de manter o software.***

## <mark style="background: #FFB8EBA6;">Resposta à crise: Engenharia de Software</mark>
Segundo a **IEEE**, Engenharia de Software é:
1. A aplicação de uma **abordagem sistemática, disciplinada e possível de ser medida** para o **desenvolvimento, operação e manutenção** do software;
2. O **estudo** dessas abordagens.

Na prática, é o conjunto de **modelos, métodos, ferramentas e práticas de qualidade** que ajudam a desenvolver software de forma organizada. O coração dessa abordagem é o **processo de software** (próximo arquivo).
