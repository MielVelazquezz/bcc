Banco de dados (ou database/base de dados) coleção de dados que são organizados para que possam ser acessados, manipulados e atualizados facilmente.

$$\text{Banco de Dados} \quad = \quad \text{Dados} + \text{Descrição dos Dados}$$
$$\text{Modelo de Dados} \quad = \quad \text{Descrição dos Dados}$$
$$\text{Dicionário de Dados} \quad = \quad \text{Conjunto de arquivos que armazenam o modelo de dados}$$

---
### SGBD - Sistema Gerenciador de Banco de Dados
Em inglês *Database Management System (DBMS)*, é um software que auxilia na definição, carga, atualização e manutenção de um banco de dados.

---

Antes de existirem os SGBDs que conhecemos hoje em dia, os dados eram armazenados em sistemas de arquivos tradicionais, gerenciados diretamente pelo sistema operacional e por programas escritos em linguagens como COBOL e Fortran.
Esse modelo é conhecido como Abordagem de Arquivos Planos (Flat Files). Cada aplicativo possuía seus próprios arquivos de dados específicos, sem uma estrutura unificada.

### Sistemas de Arquivos X SGBDs 
Os principais problemas de se usar sistemas de arquivos para manipulação desses dados é que:
- Há <mark style="background: #CACFD9A6;">redundância</mark> e <mark style="background: #CACFD9A6;">inconsistência</mark> de dados: O mesmo dado poderia se repetir em vários arquivos diferentes e se um dado mudasse em um arquivo, em outro poderia ficar desatualizado.
- <mark style="background: #CACFD9A6;">Dificuldade no acesso</mark> aos dados (consulta): Para extrair uma informação simples era necessário escrever um programa inteiro do zero.
- <mark style="background: #CACFD9A6;">Acesso concorrente</mark>: Dois programas ou usuários não podem alterar o mesmo arquivo ao mesmo tempo de forma segura. Se o usuário A e o usuário B abrirem a mesma planilha de estoque para vender o último item, o sistema operacional aceitará a alteração de quem salvar por último, gerando erros graves como a venda dupla de um produto que só tinha uma unidade.
- <mark style="background: #CACFD9A6;">Problemas de segurança</mark>: Se um usuário precisa atualizar o arquivo de funcionários para mudar o cargo de alguém, ele ganha acesso de leitura e escrita ao arquivo inteiro. Ele poderá ver (e alterar) dados sigilosos, como os salários de toda a empresa.
- <mark style="background: #CACFD9A6;">Problemas de integridade</mark>: Não há regras automáticas para proteger os dados contra erros humanos ou de software. Se um usuário digitar letras no campo de "Salário" ou colocar uma data de nascimento no ano de 2050, o arquivo aceitará o erro. Além disso, se o computador desligar no meio de uma gravação, o arquivo pode se corromper inteiramente.

### Processamento de Dados com BD
Ao contrário de Sistemas de Arquivos, - em que cada programa mandava no seu próprio pedaço de informação - o processamento com banco de dados enxerga a informação como patrimônio único e centralizado de uma empresa.

1. Dados que pertencem a uma comunidade de usuários integrados no Banco de Dados
	- Em uma empresa, os dados não pertencem ao setor de Vendas, ao RH ou ao Financeiro de forma isolada. Eles pertencem a **toda a organização (a comunidade de usuários)**.
	- O Banco de Dados unifica essas informações em um único grande sistema. O setor de Vendas insere um pedido, o Financeiro lê esse mesmo pedido para emitir a nota fiscal, e a Expedição o acessa para fazer o envio. Todos os usuários estão **integrados**, bebendo da mesma fonte de informação confiável e em tempo real.

2. Cada informação armazenada uma única vez
	- Este é o princípio da **não-redundância**. Para evitar o desperdício de espaço em disco e o risco de informações desatualizadas, cada entidade do mundo real deve ter apenas um registro oficial no banco.
	- Em vez de salvar o nome, CPF e telefone de um cliente toda vez que ele faz uma compra nova, o cliente é cadastrado **uma única vez** na tabela de `Clientes`. Nas compras dele, o banco apenas aponta para aquele cadastro único através de um código (a chave primária).

3. Eventual redundância controlada pelo sistema em computador e invisível ao usuário
	- Às vezes, por motivos de **desempenho** (para fazer o sistema rodar mais rápido), o administrador do banco de dados escolhe duplicar intencionalmente um dado em outra tabela (desnormalização). No entanto, quem cuida para que essa duplicidade não vire uma bagunça é o próprio software do SGBD, de forma automática.
	- **Por que é invisível ao usuário?** O usuário final (ou o sistema que ele usa) não precisa se preocupar em atualizar o dado nos dois lugares. Ele altera a informação em apenas um campo na tela. Por baixo dos panos, o SGBD propaga essa alteração para onde quer que o dado tenha sido duplicado, garantindo que tudo continue correto sem que o usuário sequer perceba que existia uma redundância ali.

### Para ser SGBD:
1. <mark style="background: #CACFD9A6;">Auto-Contenção</mark> (ou Natureza de Auto-Descrição): Não contém apenas os dados, mas armazena a descrição deles, seus relacionamentos e formas de acesso.
	- **Explicação simples:** Um banco de dados é como uma **biblioteca que possui seu próprio catálogo interno**. Ele não guarda apenas as informações brutas (os "livros"); ele guarda também um manual que explica o que é cada dado, qual o tamanho dele, se é um texto ou um número, e como ele se conecta a outros dados.
	- **Onde fica isso?** Essa descrição fica guardada em um lugar chamado **Catálogo do SGBD** (ou **Metadados** - _dados sobre dados_). Se o banco de dados for movido para outro computador, ele continua funcionando perfeitamente porque leva consigo a sua própria estrutura. No sistema de arquivos antigo isso não existia: o arquivo era só um amontoado de texto e o programador tinha que adivinhar a estrutura.
	
2. <mark style="background: #CACFD9A6;">Independência dos Dados:</mark> Nenhuma definição dos dados deverá estar contida nos programas da aplicação.
	- **Explicação simples:** Significa **separar a "igreja do estado"**, ou seja, separar o código do programa (o software em si) da estrutura física de onde o dado está salvo.
	- **Na prática:** Imagine que você tem um aplicativo e decide mudar o tipo de campo do CPF de "número" para "texto" no banco de dados. Com a _Independência dos Dados_, você altera isso diretamente no SGBD. O seu aplicativo (o código em Java, Python, C#) não precisa ser inteiramente reescrito ou recompilado só porque o tamanho de um campo mudou. O programa apenas "pede" o dado, e o SGBD se vira para entregar.

3. <mark style="background: #CACFD9A6;">Abstração dos Dados</mark>: O usuário possui somente uma representação conceitual dos dados, o que não inclui detalhes sobre sua forma de armazenamento real.
	- **Explicação simples:** O SGBD **esconde a complexidade física** de como os dados são salvos no HD. Para o usuário (ou para o desenvolvedor), os dados aparecem de forma simples e lógica, como tabelas bonitas com linhas e colunas (Modelo Relacional) ou gráficos fáceis de entender.
	- **Analogia:** Pensando no sistema de arquivos de um computador (as pastas). Para você, um arquivo de filme está guardado dentro da pasta "Vídeos". Isso é uma _abstração_. Na realidade física do HD (armazenamento real), esse filme está quebrado em milhões de pedacinhos de 0s e 1s espalhados por discos magnéticos ou chips de memória Flash. A abstração de dados faz a mesma coisa: ela te mostra uma tabela organizada de "Clientes" e esconde os bits, os blocos de memória e os ponteiros complexos que o computador usa por baixo dos panos.
	
4. <mark style="background: #CACFD9A6;">Visões (Views)</mark>: Permite que cada usuário visualize os dados de forma personalizada.
- **Explicação simples:** Uma _View_ (ou Visão) é como uma **janela personalizada** para o banco de dados. Em vez de dar acesso a uma tabela inteira e complexa para todo mundo, o SGBD permite criar "tabelas virtuais" personalizadas para as necessidades de cada usuário.
- **Exemplo prático:** Pense na tabela de `Funcionários`. Ela contém nome, cargo, telefone, salário e bônus.
    - O departamento de **Marketing** precisa apenas do nome e telefone para fazer contato. O SGBD cria uma _View_ para eles mostrando apenas essas duas colunas.
    - O departamento de **Contabilidade** precisa ver os salários e bônus. O SGBD cria outra _View_ para eles.
    - Ambos estão olhando para os mesmos dados, mas cada um enxerga apenas o que lhe interessa e o que tem permissão para ver.

5. <mark style="background: #CACFD9A6;">Transações</mark>: Necessita de instruções para gravar uma série de modificações simultâneas (`COMMIT`) ou cancelar essa série (`ROLLBACK`).
- **Explicação simples:** Uma transação é um conjunto de ações que **ou dá totalmente certo, ou não acontece nada**. O SGBD garante que o sistema nunca fique "pela metade" se algo der errado (como o computador desligar ou a internet cair).
- **Exemplo prático (O pedido do cliente):** Quando você compra um produto online, o sistema precisa:
    1. Diminuir 1 item do estoque.
    2. Gerar a cobrança no cartão.
    3. Criar a nota fiscal.  
        Se o sistema fizer o passo 1 e 2, mas a internet cair antes do passo 3, o banco de dados usa a instrução de **cancelar (Rollback)** e desfaz tudo, voltando o estoque ao normal. Se os três passos funcionarem, ele usa a instrução de **gravar (Commit)** para salvar tudo permanentemente.

6. <mark style="background: #CACFD9A6;">Acesso Compartilhado Automático</mark>: Permite acesso concorrente compartilhado, impedindo que um sistema sobreponha suas alterações às de outro.
- **Explicação simples:** É o mecanismo que permite que **milhares de pessoas usem o mesmo banco de dados ao mesmo tempo** sem que uma atrapalhe ou apague o trabalho da outra. O SGBD resolve isso de forma automática "por baixo dos panos".
- **Exemplo prático (Instituição financeira):** Se você e seu sócio têm uma conta conjunta com R$ 500 de saldo e tentam sacar R$ 500 ao mesmo tempo em caixas eletrônicos diferentes:
    - O SGBD cria uma fila invisível de milissegundos.
    - O primeiro saque entra no banco, o saldo vai para R$ 0 e a transação é gravada.
    - Quando o segundo saque tenta processar (um milissegundo depois), o SGBD bloqueia a operação porque o saldo já é zero. Em um sistema de arquivos antigo, os dois saques aconteceriam e a conta ficaria negativa ilegalmente.

---
### Aspectos Funcionais de um SGBD
Os SGBDs oferecem segurança, ou seja, ele dita qual usuário pode realizar tal operação sobre um tal dado; Possui intolerância a falhas, logo há recuperação em caso de falhas (visível ao usuário); E além disso, oferece controle de acesso concorrente, onde é possível que múltiplos usuários possam acessar e atualizar o banco de dados ao mesmo tempo.

### Abstração de Dados
"Abstração de Dados" é a habilidade mental que permite aos seres humanos enxergarem os problemas do mundo real com vários graus de detalhe, dependendo do contexto do problema. 

Por exemplo: 
Um sistema de uma faculdade quer cadastrar um novo aluno.
O que será de interesse da faculdade é o CPF, nome, matrícula, outros documentos, ...
O aluno tem cor de cabelo, altura, peso, time de futebol, ... -> Mas o analista de sistema abstrai (ignora) esses dados porque não terão relevância para o contexto do problema.

A abstração se dá em três níveis, também chamada de **Arquitetura de Três-Esquemas**:
- <mark style="background: #CACFD9A6;">Nível de Visão ou Externo (visão do usuário)</mark>: O banco de dados podem ter milhares de informações, mas o usuário só verá o que lhe interessa.
- <mark style="background: #CACFD9A6;">Nível Conceitual</mark>: É o coração do banco de dados, pois descreve a lógica de toda base de dados da empresa de forma unificada:
	- **Visão de conjunto de usuário**: Não importa o que o Usuário A ou B preferem ver; define-se a estrutura global (quais tabelas existem, como `Clientes`, `Vendas` e `Produtos`)
	- **Descrição mais abstrata e sem detalhes de implementação:** Define o _quê_ está armazenado e quais os relacionamentos e regras entre os dados (ex: "toda venda precisa ter um cliente válido"
	- **Independente de SGBD:** A modelagem feita aqui (como um diagrama de Entidade-Relacionamento) descreve o negócio em si. Ela serve independentemente se você vai usar o SGBD MySQL, PostgreSQL ou Oracle para salvar os dados no futuro.
- <mark style="background: #CACFD9A6;">Nível Físico ou Interno</mark>: É a camada mais baixa e complexa, que lida diretamente com o hardware e a engenharia do computador.
	- **Modelo lógico e estruturas de armazenamento:** Define _como_ os dados estão guardados fisicamente no disco rígido (HD ou SSD).
	- **Como os dados estão armazenados:** Especifica os formatos de arquivos, as técnicas de compressão de dados, os caminhos de diretórios no sistema operacional e os algoritmos de busca (como índices e árvores B+) usados para que o SGBD ache uma informação em milissegundos. O usuário final nunca vê esse nível.

****Resuminho:

| Níveis     | Analogia                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Externo    | É o cardápio que o cliente recebe na mesa. Mostra os pratos disponíveis de forma bonita e personalizada.                                    |
| Conceitual | É a receita escrita pelo chef. Ela mostra os ingredientes necessários e como eles se combinam.                                              |
| Interno    | É a cozinha. Como as panelas são organizadas, a temperatura exata do forno e em qual prateleira da geladeira os ingredientes são guardados. |

### Linguagens do SGBD:

#### DDL - Data Definition Language 
Usado para descrever o modelo lógico: 
- ```sql
	CREATE -- cria novos objetos (tabelas, bancos de dados, visões)
	ALTER -- altera a estrutura de um objeto existente (adicionar ou remover colunas)
	DROP -- apaga a tabela inteira e sua estrutura
  
  /* ==================== EXEMPLOS ====================*/
	CREATE TABLE Clientes (
		id_cliente INT PRIMARY KEY,
		nome VARCHAR(100),
		cpf VARCHAR(11)
	);
	
	ALTER TABLE Clientes ADD telefone VARCHAR(20);
	
	DROP TABLE Clientes;
	
  ```

#### DML - Data Manipulation Language
Instruções que trabalham sobre a base de dados: 
```SQL
	
	INSERT -- insere novas informações na tabela.
	UPDATE -- atualiza dados que já existem.
	DELETE -- apaga linhas específicas de dados de dentro de uma tabela.
	SELECT -- busca e recupera as informações 
	
	/* ==================== EXEMPLOS ====================*/
	INSERT INTO Clientes (id_cliente, nome, cpf) 
	VALUES (1, 'Maria Silva', '12345678900');
	
	UPDATE Clientes 
	SET telefone = '11999999999' 
	WHERE id_cliente = 1;
	
	DELETE FROM Clientes 
	WHERE id_cliente = 1;
	
	SELECT * FROM Clientes;

```

#### DCL - Data Control Language
Usado para controlar quem tem acesso a ver/manipular dados do banco de dados: 

```sql
	
	GRANT -- concede permissões de acesso a um usuário.
	REVOKE -- retira ou cancela as permissões que haviam sido dadas.

	/* ==================== EXEMPLOS ====================*/
	GRANT SELECT, INSERT ON Clientes TO vendedor;
	
	REVOKE DELETE ON Clientes FROM vendedor;

```
